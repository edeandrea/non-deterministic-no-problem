# Task 07: OpenShift Wiring for the Lease

**Type:** Deployment Configuration

## Goal

On OpenShift the app elects its intake leader through a Kubernetes Lease, with the least RBAC that needs, and
`oc scale deployment/parasol-app --replicas=3` just works. The default stays one replica.

## What to Do

- `%openshift`: `parasol.intake.leadership.mode: kubernetes-lease`.
- **RBAC**, generated by the OpenShift extension rather than hand-written: a Role in the app's namespace with
  `coordination.k8s.io` `leases`: `get`, `create`, `update` (add `list`/`watch` only if fabric8's `LeaseLock` needs
  them; check), bound to the app's ServiceAccount (`quarkus.openshift.rbac.roles.*`,
  `quarkus.openshift.rbac.role-bindings.*`). Turn off anything broader the kubernetes-client extension would generate by
  default (`quarkus.kubernetes-client.generate-rbac`); check what lands in `target/kubernetes/openshift.yml`.
- **No `POD_NAME` needed:** the Lease identity defaults to the host name, which is the pod name on Kubernetes (`parasol.intake.leadership.identity` overrides it).
- **`replicas: 1`** stays, with its comment rewritten: the intake is safe to scale; one application instance leads the intake (a Lease),
  every application instance serves the UI/REST/chat; see README → *Scaling*.
- Check the Deployment strategy: the app has no PVC, so `RollingUpdate` is fine. The new application instance becomes ready as a
  follower, and takes the Lease when the old application instance releases it on shutdown. Say so in the comment.
- `deploy-to-openshift.sh`: nothing, unless the generated RBAC needs applying separately. Check.
- `src/main/kubernetes/dependencies.yml`: nothing for the app's own RBAC (it's generated). Confirm the database PVC
  and the migration path decided in task 02.

## Files/Areas

- `deploy-to-openshift.sh` (maybe)
- `README.md` (*Single replica* becomes *Scaling*: how to scale, how to see the leader with `oc get lease
  parasol-intake-leader`, what a follower does)

## Key Points

- **There's no cluster here to test against** (as for #218/#290). Verification is the generated manifest
  (`./mvnw package -DskipTests -Dquarkus.profile=openshift` → `target/kubernetes/openshift.yml`): the Role, the
  RoleBinding, the env var and the replica count. Say plainly in the PR that it wasn't deployed.
- Keep the `connects-to` annotation as it is: it names Deployments, and none is added.
- The Lease name must be unique per namespace, not per app instance: two copies of the demo in one namespace would
  share it. Note it in the README.
