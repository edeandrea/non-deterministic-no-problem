# Task 02: OpenShift ConfigMap and Roundcube Deployment

**Type:** Build

## Goal

On OpenShift, Roundcube loads the same plugin and map as in dev mode, with an environment identical to the Compose
file.

## What to Do

- **`src/main/kubernetes/dependencies.yml`:**
  - A `roundcube-identities` ConfigMap holding both PHP files from task 01 as keys.
  - The Roundcube Deployment mounts it with `subPath` to the same two paths
    (`/var/www/html/plugins/parasol_identities/parasol_identities.php`, `/var/roundcube/config/parasol-identities.php`)
    and sets `ROUNDCUBEMAIL_PLUGINS` exactly as Compose does. Update the comment above the Deployment.
- **Decide how the ConfigMap stays in sync with the PHP sources**, and record the decision in `PLAN.md`:
  - **Inline in `dependencies.yml`**, with a comment that it copies `src/main/docker/roundcube/` (simple; the same
    duplication the Compose/Kubernetes parity already has); or
  - **Generated by `deploy-to-openshift.sh`** (`oc create configmap roundcube-identities --from-file=… --dry-run=client -o yaml | oc apply -f -`),
    so the files are the only copy, at the cost of `dependencies.yml` not being complete on its own.
  Ask the user if neither is clearly better.
- Check the restricted SCC still works: the mounted files are read-only and owned by root, which the arbitrary UID can
  read (ConfigMap volumes default to mode `0644`).

## Key Points

- **Parity:** image, env and mounted content identical to `compose-devservices.yml` (CLAUDE.md: change both together).
  Check it mechanically, as #215's task 03 did.
- **Validate offline** with kubeconform `-strict` via podman, as recorded in `.tasks/04-gh215-greenmail-roundcube/PLAN.md`
  (Caveats): the default schemas plus `melmorabity/openshift-json-schemas` `v4.14-standalone-strict` for `Route`.
  `oc apply --dry-run=client` needs a reachable cluster.
- Optionally run the image locally with `--user 1000680000:0` and the files mounted, to mimic the SCC.

## Done When

- [ ] ConfigMap and Deployment changes in place, and the sync decision recorded in `PLAN.md`
- [ ] Compose and Kubernetes environments and mounted content checked identical
- [ ] kubeconform `-strict` passes
- [ ] The live cluster check is listed under Manual Checks in `PLAN.md` for the user
